Core Engine

The Analysis Pipeline

When you trigger an analysis, the system walks through a multi-stage pipeline that breaks your codebase into understandable pieces, sends each to Claude for review, and synthesizes everything into a unified report.

1. Repository Ingestion
The system clones your repository (via git clone --depth 1), extracts a ZIP upload, or reads from a local path. Binary files, node_modules, and other noise are automatically filtered out.
2. File Indexing
Every source file is walked, its language detected (30+ supported), and a regex-based parser extracts symbols — classes, functions, exports, and imports. Each file's content is hashed (SHA-256) and stored with metadata.
3. Dependency Graph Construction
Import statements are resolved to actual files in the repository. Relative imports like ./utils are resolved with extension probing (.ts, .tsx, .js, /index.ts, etc). The result is a full graph of internal and external dependencies.
4. Smart Chunking
Files are grouped into logical modules by their top-level directory. Each module is checked against a 60,000-token target. Large modules are automatically split into sub-chunks so that each piece fits comfortably within Claude's context window.
5. AI Module Analysis
Each module chunk is sent to Claude with a specialized prompt. Up to 3 modules are analyzed in parallel. Claude reviews each module for design patterns, anti-patterns, security concerns, complexity hotspots, tech debt, and improvement opportunities. Results come back as structured JSON.
6. Architecture Synthesis
All module-level analyses are combined and sent to Claude for a holistic synthesis. This step identifies cross-cutting concerns, architecture style, system-wide patterns, and produces the unified findings list covering security issues, scalability risks, and improvement suggestions.
7. Report Generation
Findings are organized into a structured report with sections: Executive Summary, Architecture Patterns, Issues & Anti-patterns, Security Findings, Scalability Risks, Improvement Suggestions, and Technical Debt. Reports are rendered as navigable markdown in the UI.

Resilient by Design

Each chunk is independently retried up to 3 times with exponential backoff. If a chunk fails permanently, the analysis continues with the remaining modules. Only if more than 50% of chunks fail does the entire analysis stop. Token usage is tracked throughout for cost visibility.

AI Strategy

Claude Prompt Templates

ArchLens uses five specialized prompts, each designed to extract a different dimension of architectural insight. Every prompt asks Claude to respond with structured JSON for reliable parsing.

Prompt 1

Module Analysis

Claude acts as a senior staff engineer reviewing a single module. It receives the full source code of every file in the module along with dependency context.

Patterns Used Anti-patterns Complexity Hotspots Security Concerns Tech Debt Strengths Improvements
Prompt 2

Architecture Synthesis

Claude combines all module-level analyses into a unified architecture review. It sees condensed summaries (not full code) from every module plus the dependency graph overview.

Architecture Summary Architecture Style Cross-cutting Concerns Potential Problems Security Issues Scalability Risks Onboarding Notes
Prompt 3

Security Audit

Claude acts as a dedicated security engineer, focusing exclusively on vulnerabilities. Findings are classified using CWE IDs where applicable, with exploit scenarios and fix hints.

Vulnerabilities + CWE Security Posture Missing Controls Exploit Scenarios
Prompt 4

Code Quality

Claude evaluates maintainability, readability, naming conventions, error handling quality, and testing indicators. Each dimension gets a 1–10 score.

Quality Score Readability Maintainability Naming Error Handling Code Smells
Prompt 5

Dependency Review

Claude analyzes the full dependency structure — both external packages and internal module coupling. It detects circular dependencies, layering violations, and suggests better boundaries.

External Deps Assessment Circular Dependencies Coupling Assessment Module Boundaries

REST API

API Endpoints

All endpoints live under /api/v1 and require an X-API-Key header. The API returns a standard {success, data, error, meta} envelope.

Repositories

MethodEndpointWhat It Does
POST/repositoriesCreate a new repository and start the ingestion process (clone/extract)
GET/repositoriesList all repositories with pagination and optional status filter
GET/repositories/:idGet full details for a single repository including language breakdown and stats
DELETE/repositories/:idDelete a repository and cascade-delete all analyses, findings, and reports
GET/repositories/:id/filesList all indexed source files with language, size, and extracted symbols
POST/repositories/:id/reindexRe-trigger the ingestion and indexing process from scratch

Analyses

MethodEndpointWhat It Does
POST/repositories/:id/analysesStart a new analysis (full, architecture, code_quality, security, or dependencies)
GET/repositories/:id/analysesList all analyses for a repository with status and progress
GET/analyses/:idGet a single analysis with real-time progress (poll this for live updates)
GET/analyses/:id/findingsGet findings with optional category and severity filters

Reports

MethodEndpointWhat It Does
POST/analyses/:id/reportsGenerate a report from a completed analysis (full_review, architecture_overview, onboarding, tech_debt)
GET/reports/:idGet a report with all its markdown sections
GET/repositories/:id/reportsList all reports for a repository

Dependency Graphs

MethodEndpointWhat It Does
GET/repositories/:id/graphGet the file-level dependency graph with nodes and edges for visualization
GET/repositories/:id/graph/modulesGet a module-level (clustered) view of dependencies with connection weights
Data Model

Database Schema

Seven PostgreSQL tables track everything from raw files to AI-generated findings. All use UUIDs and cascade deletes to keep data consistent.

repositories

Name, source, status, languages, stats

files

Path, language, size, lines, symbols

dependencies

Source file → target file with type

analyses

Type, status, progress, token usage

analysis_chunks

Module chunks with Claude responses

findings

Category, severity, description, suggestion

reports

Type, sections (markdown), summary

Relationships

-- Data flows through these relationships: repository 1 ─── * files (indexed source files) repository 1 ─── * dependencies (import/require links between files) repository 1 ─── * analyses (AI review sessions) analysis 1 ─── * analysis_chunks (module-level Claude calls) analysis 1 ─── * findings (extracted insights) analysis 1 ─── * reports (generated documents) -- All children cascade-delete when the parent is removed.

Status Lifecycles

Analysis Status

queued → chunking → analyzing → synthesizing → completed

Setup & Run

# 1. Clone and enter the project git clone <repo-url> && cd archlens # 2. Set up environment variables cp .env.example .env # Edit .env and add your ANTHROPIC_API_KEY # 3. Install all dependencies make install # 4. Start Postgres and Redis containers make infra # 5. Create database tables make migrate # 6. Start all development servers make dev

Once running, open http://localhost:3000 for the web UI, or hit the API directly at http://localhost:3001.

# Build and start all 5 services in Docker make docker-up # Stop everything make docker-down
